言語とローカライズ

Mica Minecraft Launcher は 17 の言語でインターフェースを表示でき、初回起動時に 適切な言語を自動で選択します。検出された言語は、設定からいつでも 変更できます。

ランチャーが言語を選ぶ仕組み

ランチャーは起動するたびに、次の順序で使用する言語を 決定します:

  1. 保存済みの手動設定 — 設定 → 外観 → 言語で設定している場合。これが常に優先されます。
  2. オペレーティングシステムの言語 — 標準の JVM ロケールから 検出します。Windows では「地域 / 言語」の設定、 macOS では「システム設定」→「言語と地域」、 Linux では LANG / LC_* 環境変数です。
  3. 英語（米国） — プラットフォームが言語ではないロケール （例: POSIX や C）を報告した場合や、OS の言語が翻訳を同梱している 17 の言語に 含まれない場合のフォールバックです。
言語の変更は再起動後に反映されます

設定で言語を切り替えると設定値はすぐに更新されますが、 すでに表示されている画面は、ランチャーを再起動するまで以前の言語のままです。 ドロップダウンを変更すると、設定画面自体にもこのことが 表示されます。

手動で言語を設定する

  1. ナビゲーションバーから 設定 を開きます （または Ctrl+, / Cmd+, を押します）。
  2. 外観 タブに切り替えます。
  3. 言語 ドロップダウンから言語を選びます。 最初の項目（「OS の言語を使用」）を選ぶと上記の自動検出に戻り、 OS から判定される言語が括弧内に 表示されます。
  4. 保存 をクリックします。ランチャーを再起動すると、新しい 言語がすべての画面に適用されます。

対応言語

ランチャーには、英語に加えて、世界で最も話者の多い 17 の言語の 翻訳が同梱されています:

  • アラビア語 (عربي)
  • 中国語（簡体字）(简体中文)
  • 中国語（繁体字）(繁體中文)
  • オランダ語 (Nederlands)
  • 英語（ソース言語）
  • フランス語 (Français)
  • ドイツ語 (Deutsch)
  • ヒンディー語 (हिंदी)
  • イタリア語 (Italiano)
  • 日本語 (日本語)
  • 韓国語 (한국어)
  • ポーランド語 (Polski)
  • ポルトガル語（ブラジル）(Português do Brasil)
  • ロシア語 (Русский)
  • スペイン語 (Español)
  • スウェーデン語 (Svenska)
  • トルコ語 (Türkçe)

各言語は BCP-47 タグ（例: fr-FR、 pt-BR、zh-CN）で識別されます。一覧はランチャーのソースの SupportedLocales.ENTRIES にあり、 プロパティファイルは src/main/resources/lang/ に DisplayStrings_<tag>.properties として並んでいます。

翻訳の品質と問題の報告

英語以外の言語の翻訳は、英語のソースバンドルに対して Google 翻訳を呼び出す スクリプトで生成され、{0} のようなパラメーターのプレースホルダーが 翻訳後もそのまま残るよう後処理されています。出力の品質は良好ですが完璧ではありません — 特に短い UI ラベル（1 語のボタンや単独の名詞）では、英語にあった文脈が 失われることがあります。

不自然な翻訳を見つけた場合は、GitHub で issue を作成するのが最善です。 キー名（例: browse.filter.type.label）、 ロケール、現在の表示、修正案を記載してください。 スクリプトは既定では不足しているキーだけを補うため、手作業での修正は 次回の再生成後も残ります。

新しい言語の追加

使用している言語が上の一覧になく、翻訳に協力したい場合は、 次の手順で貢献できます:

  1. SupportedLocales.ENTRIES （Java）と tools/i18n/translate-locales.js（Node）の TARGET_LOCALES に新しい項目を追加します。
  2. cd tools/i18n && npm run translate を実行します — スクリプトが英語のソースから最初の DisplayStrings_<tag>.properties を生成します。
  3. 生成されたファイルを確認し、不自然な箇所を手作業で修正してから、 プルリクエストを作成します。

tools/i18n/translate-locales.js スクリプトは差分のみを処理します。 再実行しても、対象ファイルにまだ存在しないキーだけが翻訳されるため、 手作業での修正はその後のランチャーのアップデートでも 保持されます。
