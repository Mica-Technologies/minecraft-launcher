JVM プリセット

設定 → 詳細の JVM プリセット ドロップダウンでは、ランチャーが Minecraft を 起動するときに JVM に渡す引数のセットを名前で選びます。これらの引数はガベージコレクターを調整し、 ヒープ領域のサイズを制御し、GC ログの有効 / 無効を切り替えます。ゲーム自体の動作は変わらず、 ゲームを動かす JVM のメモリ管理の方法だけが変わります。

適切なプリセットを選ぶことが特に重要なのは、大規模な MODパック（MOD 200 個以上）です。 数千のチャンクの読み込みと解放のたびに GC が後片付けをしなければならないためです。 バニラや小規模な MODパックではどのプリセットでも問題なく、 既定の「Performance」で十分に動作します。

パフォーマンス（Aikar のフラグ）

既定のプリセットで、ほとんどのユーザーにおすすめです。G1 ガベージコレクターを使い、 Aikar（Paper Minecraft サーバーの作者）が何年も前に公開し、今も多くのチュートリアルで 引用されているパラメーター調整を適用します。激しいプレイ中の GC 停止によるカクつきを最小限に抑えるよう設計されています。

おすすめの用途: RAM を 6 GB 以上割り当てた MODパック、 負荷がかかると定期的にフレームレートが落ち込む、MOD を大量に入れたパック。

省メモリ

空き RAM が少ないシステム向けの、絞り込んだフラグです。G1 を使いつつ停止時間の目標を短く、 ヒープ領域を小さくし、スループットを多少犠牲にして、メモリに余裕がない状況での予測可能性を高めます。

おすすめの用途: システム全体の RAM が 8 GB 以下のシステム、 バッテリー駆動中のノート PC、または他のアプリと並行して複数の MODパックを 実行したい場合。大規模な MODパック（MOD 200 個以上）にはおすすめしません。 同じ割り当て量でも、Aikar's Flags のほうが効率よくメモリを回収できるためです。

デバッグ

Performance のフラグに加えて、GC の詳細ログと Java のアサーションを 有効にします。MODパックのインストールフォルダーに {@code gc.log} ファイルを書き込み、 すべての GC イベントをタイムスタンプ付きで記録します。主に MOD 開発者や、再現性のある OOM クラッシュを調べる人向けです。常にわずかなオーバーヘッドが加わるため、普段のプレイでは有効のままにしないでください。

おすすめの用途: GC 停止に関する苦情の調査、 「1 分ごとに数秒間応答しなくなる」といった報告の 調査。

なし

引数リストは空で、JVM は独自の既定値を使用します。体感できるパフォーマンスの問題が プリセットのフラグ自体によるものかどうかを確認するのに役立ちます（まれですが、Aikar's Flags が 書かれた当時より JDK のバージョンがかなり新しい場合には起こり得ます）。

おすすめの用途: プリセットが特定の MOD や JDK のリリースと相性が悪いと疑われるときの 基準となる動作の確認。

RAM の割り当てに関する注意

プリセットは起動時に JVM を調整しますが、JVM が使用できるメモリ量を決めるのは、 設定 → アカウント / ゲームにあるランチャーの 最小 RAM と 最大 RAM のスライダーです。適切な量は MODパックによって異なります:

  • バニラの Minecraft: 2 GB で十分です。
  • 軽量な MODパック（MOD 50 個以下）: 4 GB。
  • 中規模の MODパック（MOD 50～150 個）: 6 GB。
  • 重い MODパック（MOD 150 個以上、シェーダーあり）: 8～12 GB。
  • 非常に重い MODパック（MOD 300 個以上、カスタムのワールド生成）: 12～16 GB。
警告

システムに余裕がある以上の RAM を割り当てると、Minecraft がディスクへの スワップを起こし、カクつきが改善するどころか悪化します。 最大 RAM はシステムの合計 RAM の半分以下にしてください。 16 GB のシステムなら、Minecraft に割り当てるのは 8 GB までにしてください。

カスタムフラグ

設定のプリセットのドロップダウンの下にある入力欄は編集できます。 プリセットが合わない場合は、独自の引数文字列を貼り付けることができます。 よく追加されるもの:

  • -XX:+UseZGC — Z ガベージコレクターに切り替えます （停止時間が短く、JDK 15 以降が必要）。非常に大きなヒープ（32 GB 以上）では G1 より高い性能を出すこともありますが、一般的な Minecraft の環境では G1 から変更する価値はあまりありません。
  • -Dfile.encoding=UTF-8 — 既定の文字セットが Latin-1 になり得る Windows で、 MOD が ASCII 以外の内容を含む設定ファイルを 生成する場合に役立ちます。
  • -Xss2M — スレッドのスタックサイズを JVM の既定値から 増やします。呼び出しの階層が深い MODパック（重いワールド生成 MOD、大規模なディメンション生成 MOD）で必要になることがあります。

カスタムフラグに誤りがあると、「Error: Could not create the Java Virtual Machine」や 「Unrecognized VM option」といったメッセージとともに起動に失敗します。 これらが表示された場合は、カスタム欄を触る前に、まず Performance に戻して もう一度試してください。
