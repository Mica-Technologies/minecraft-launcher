JVM 預設

「設定 → 進階」中的 JVM 預設組合下拉式選單，用來選擇 啟動器在啟動 Minecraft 時傳給 JVM 的一組具名參數。 這些參數會調校垃圾回收器、控制堆積區域 大小，並切換 GC 記錄；它們不會改變遊戲本身的 行為，只會改變承載遊戲的 JVM 如何管理記憶體。

選擇合適的預設組合，對大型模組包（200 個以上的 模組）最為重要，因為 GC 必須清理數千個區塊載入與 卸載後留下的資料。對於原版與小型模組包，任何預設組合都沒問題， 預設的「Performance」就很好用。

Performance (Aikar's Flags)

預設的組合，建議絕大多數使用者使用。使用 G1 垃圾回收器，並採用 Aikar（Paper Minecraft 伺服器的作者）多年前發布、至今仍有許多教學引用的 參數調校。目的是盡量減少高負載遊玩期間因 GC 暫停造成的卡頓。

最適合：配置 6 GB 以上記憶體的模組包， 以及您曾注意到在高負載下畫面更新率會週期性頓一下的 重度模組包。

Low Memory（低記憶體）

為可用記憶體不多的系統精簡過的旗標。使用 G1，並搭配 較短的暫停目標與較小的堆積區域，犧牲部分 傳輸量，以換取在記憶體吃緊時的可預測性。

最適合：系統總記憶體 ≤ 8 GB 的電腦、 使用電池的筆記型電腦，或您想在其他應用程式執行的同時 讓多個模組包一起執行的情況。不建議用於大型模組包 （200 個以上的模組），因為在相同的總配置下， Aikar 的旗標能更有效率地回收記憶體。

Debug（偵錯）

Performance 旗標，再加上 GC 詳細記錄與 Java 斷言 功能。會在模組包的安裝資料夾中寫入 {@code gc.log} 檔案， 以時間戳記記錄每一次 GC 事件。主要適用於模組 開發人員，以及要診斷可重現的 OOM 崩潰的人；它會帶來 少量的持續性額外負擔，因此平常遊玩時請勿保持開啟。

最適合：診斷 GC 暫停相關問題， 調查「每分鐘都會停止回應幾秒鐘」之類的 回報。

None（無）

空的參數清單，JVM 會使用其自身的預設值。適用於 測試察覺到的效能問題是否由預設組合的旗標本身 所造成（雖然少見，但如果 JDK 版本比撰寫 Aikar 旗標時 新得多，就有可能發生）。

最適合：當懷疑某個預設組合與特定模組或 JDK 版本互動不良時，確認基準行為。

記憶體配置注意事項

預設組合會在啟動時調校 JVM，但 JVM 可以使用多少記憶體， 是由「設定 → 帳號／遊戲」中啟動器的 最小記憶體與最大記憶體滑桿 決定的。合適的數量取決於模組包：

  • 原版 Minecraft：2 GB 就很充裕。
  • 輕量模組包（≤ 50 個模組）：4 GB。
  • 中型模組包（50-150 個模組）：6 GB。
  • 重度模組包（150 個以上的模組、光影）：8-12 GB。
  • 超重度模組包（300 個以上的模組、自訂世界生成）：12-16 GB。
警告

配置超過系統所能負擔的記憶體，會導致 Minecraft 將資料置換到磁碟，讓卡頓變得更嚴重，而不是改善。 請將最大記憶體維持在系統總記憶體的一半以下。 16 GB 的系統不應配置超過 8 GB 給 Minecraft。

自訂旗標

設定中位於預設組合下拉式選單下方的欄位是可以編輯的；如果 預設組合不符合您的需求，可以貼上您自己的參數字串。 常見的附加項目：

  • -XX:+UseZGC：切換為 Z 垃圾回收器 （低暫停，需要 JDK 15 以上）。在非常大的堆積 （32 GB 以上）上有時表現優於 G1，但在一般的 Minecraft 配置上， 通常不值得從 G1 改用。
  • -Dfile.encoding=UTF-8：當模組在 Windows 上產生 含有非 ASCII 內容的設定檔，而預設字元集 可能是 Latin-1 時很有用。
  • -Xss2M：將執行緒堆疊大小提高到超過 JVM 預設值；某些呼叫鏈很深的模組包（重度世界生成 模組、大型維度產生器）需要此設定。

自訂旗標中的錯誤會導致啟動失敗，並顯示 「Error: Could not create the Java Virtual Machine」或 「Unrecognized VM option」之類的訊息。如果您看到其中一種，請先切換回 Performance 再試一次，然後才考慮使用自訂欄位。
