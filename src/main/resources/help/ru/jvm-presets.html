Предустановки JVM

Раскрывающийся список Предустановка JVM в разделе «Настройки → Дополнительно» выбирает именованный набор аргументов, которые лаунчер передаёт JVM при запуске Minecraft. Эти аргументы настраивают сборщик мусора, управляют размером областей кучи и включают журналирование GC — они не меняют поведение самой игры, а только то, как JVM, в которой она работает, управляет памятью.

Правильный выбор предустановки важнее всего для крупных модпаков (200+ модов), где GC приходится убирать за тысячами загружаемых и выгружаемых чанков. Для ванильной игры и небольших модпаков подойдёт любая предустановка, а стандартная «Performance» работает хорошо.

Производительность (флаги Aikar)

Предустановка по умолчанию, рекомендуемая для подавляющего большинства пользователей. Использует сборщик мусора G1 с настройками параметров, которые Aikar (автор сервера Paper для Minecraft) опубликовал много лет назад и на которые до сих пор ссылаются многие руководства. Предназначена для минимизации подтормаживаний из-за пауз GC в напряжённых игровых моментах.

Подходит для: модпаков, которым выделено 6+ ГБ ОЗУ, сильно модифицированных сборок, в которых вы замечали периодические просадки частоты кадров под нагрузкой.

Мало памяти

Облегчённые флаги для систем с небольшим запасом ОЗУ. Использует G1 с более коротким целевым временем паузы и меньшими областями кучи, жертвуя частью пропускной способности ради предсказуемости при нехватке памяти.

Подходит для: систем, в которых всего ≤ 8 ГБ ОЗУ, ноутбуков, работающих от батареи, или случаев, когда нужно держать несколько модпаков запущенными вместе с другими приложениями. Не рекомендуется для крупных модпаков (200+ модов), где флаги Aikar освобождают память эффективнее даже при том же общем объёме выделенной памяти.

Отладка

Флаги Performance плюс подробное журналирование GC и включённые утверждения Java. Записывает файл {@code gc.log} в папку установки модпака, в котором фиксируется каждое событие GC с отметками времени. Полезна в основном разработчикам модов и тем, кто разбирается с повторяющимися сбоями OOM; добавляет небольшие постоянные накладные расходы, поэтому не оставляйте её включённой для обычной игры.

Подходит для: диагностики жалоб на паузы GC, расследования сообщений вида «игра каждую минуту на несколько секунд перестаёт отвечать».

Нет

Пустой список аргументов — JVM использует собственные значения по умолчанию. Полезно для проверки того, не вызвана ли предполагаемая проблема с производительностью самими флагами предустановки (редко, но возможно, если версия JDK намного новее времени, когда были написаны флаги Aikar).

Подходит для: проверки базового поведения, когда есть подозрение, что предустановка плохо сочетается с конкретным модом или выпуском JDK.

Заметки о выделении ОЗУ

Предустановки настраивают JVM при запуске, но то, сколько памяти разрешено использовать JVM, определяют ползунки лаунчера Минимум ОЗУ и Максимум ОЗУ в разделе «Настройки → Учётная запись / Игра». Нужный объём зависит от модпака:

  • Ванильный Minecraft: 2 ГБ более чем достаточно.
  • Лёгкие модпаки (≤ 50 модов): 4 ГБ.
  • Средние модпаки (50-150 модов): 6 ГБ.
  • Тяжёлые модпаки (150+ модов, шейдеры): 8-12 ГБ.
  • Экстремальные модпаки (300+ модов, собственная генерация мира): 12-16 ГБ.
Предупреждение

Если выделить больше ОЗУ, чем система может отдать, Minecraft начнёт использовать файл подкачки на диске, и подтормаживания станут сильнее, а не слабее. Держите максимум ОЗУ не выше половины общего объёма ОЗУ системы. В системе с 16 ГБ не стоит выделять Minecraft больше 8 ГБ.

Собственные флаги

Поле в настройках под раскрывающимся списком предустановок можно редактировать — вы можете вставить собственную строку аргументов, если ни одна предустановка не подходит. Частые дополнения:

  • -XX:+UseZGC — переключиться на сборщик мусора Z (низкие паузы, требуется JDK 15+). Иногда превосходит G1 на очень больших кучах (32 ГБ+), но в типичных конфигурациях Minecraft менять G1 на него обычно не стоит.
  • -Dfile.encoding=UTF-8 — полезно, когда моды создают файлы конфигурации с не-ASCII содержимым в Windows, где кодировкой по умолчанию может быть Latin-1.
  • -Xss2M — увеличивает размер стека потока по сравнению со значением JVM по умолчанию; это нужно некоторым модпакам с глубокими цепочками вызовов (тяжёлые моды генерации мира, крупные генераторы измерений).

Ошибки в собственных флагах проявляются как сбои запуска с сообщениями вроде «Error: Could not create the Java Virtual Machine» или «Unrecognized VM option». Если вы видите одно из них, вернитесь к Performance и попробуйте снова, прежде чем обращаться к полю собственных флагов.
