Langue et localisation

Mica Minecraft Launcher affiche son interface en 17 langues et choisit automatiquement la bonne au premier lancement. Vous pouvez aussi remplacer la langue détectée à tout moment depuis les Paramètres.

Comment le lanceur choisit une langue

À chaque démarrage, le lanceur détermine la langue active dans l'ordre suivant :

  1. Votre choix enregistré, si vous en avez défini un dans Paramètres → Apparence → Langue. Ce choix est toujours prioritaire.
  2. La langue de votre système d'exploitation, détectée via les paramètres régionaux standard de la JVM. Sous Windows, il s'agit de votre réglage Région / Langue ; sous macOS, de Réglages Système → Langue et région ; sous Linux, de l'environnement LANG / LC_*.
  3. Anglais (États-Unis) en dernier recours si la plateforme indique des paramètres régionaux sans langue (par ex. POSIX ou C), ou si la langue de votre système ne fait pas partie des 17 langues pour lesquelles nous fournissons une traduction.
Le changement de langue prend effet après un redémarrage

Modifier la langue dans les Paramètres met à jour la préférence immédiatement, mais les écrans déjà affichés restent dans la langue précédente jusqu'au redémarrage du lanceur. La page Paramètres vous le rappelle d'ailleurs lorsque vous modifiez la liste déroulante.

Choisir une langue manuellement

  1. Ouvrez les Paramètres depuis la barre de navigation (ou appuyez sur Ctrl+, / Cmd+,).
  2. Passez à l'onglet Apparence.
  3. Choisissez une langue dans la liste déroulante Langue. La première entrée (« Utiliser la langue du système ») rétablit la détection automatique décrite ci-dessus et indique entre parenthèses la langue que le système d'exploitation sélectionnerait.
  4. Cliquez sur Enregistrer. Redémarrez le lanceur pour voir la nouvelle langue appliquée à tous les écrans.

Langues prises en charge

Le lanceur est traduit dans les 17 langues les plus parlées au monde, en plus de l'anglais :

  • Arabe (عربي)
  • Chinois simplifié (简体中文)
  • Chinois traditionnel (繁體中文)
  • Néerlandais (Nederlands)
  • Anglais (langue source)
  • Français (Français)
  • Allemand (Deutsch)
  • Hindi (हिंदी)
  • Italien (Italiano)
  • Japonais (日本語)
  • Coréen (한국어)
  • Polonais (Polski)
  • Portugais du Brésil (Português do Brasil)
  • Russe (Русский)
  • Espagnol (Español)
  • Suédois (Svenska)
  • Turc (Türkçe)

Chaque langue est identifiée par son étiquette BCP-47 (par ex. fr-FR, pt-BR, zh-CN). La liste se trouve dans SupportedLocales.ENTRIES dans le code source du lanceur ; les fichiers de propriétés se trouvent à côté, sous la forme DisplayStrings_<tag>.properties, dans src/main/resources/lang/.

Qualité des traductions et signalement des problèmes

Les traductions dans les langues autres que l'anglais sont générées par un script qui interroge Google Traduction à partir du fichier source anglais, puis retraite les paramètres de substitution afin que des éléments comme {0} soient conservés intacts. Le résultat est bon mais pas parfait — en particulier, les libellés courts de l'interface (boutons d'un seul mot, noms isolés) perdent parfois le contexte qu'ils avaient en anglais.

Si vous repérez une mauvaise traduction, le mieux est d'ouvrir un ticket sur GitHub en indiquant le nom de la clé (par ex. browse.filter.type.label), vos paramètres régionaux, le texte affiché actuellement et une proposition de correction. Les corrections manuelles sont conservées lors de la régénération suivante, car le script ne complète par défaut que les clés manquantes.

Ajouter une nouvelle langue

Si votre langue ne figure pas dans la liste ci-dessus et que vous souhaitez contribuer une traduction, voici la marche à suivre :

  1. Ajoutez une nouvelle entrée à SupportedLocales.ENTRIES (Java) et à TARGET_LOCALES dans tools/i18n/translate-locales.js (Node).
  2. Exécutez cd tools/i18n && npm run translate — le script générera le fichier initial DisplayStrings_<tag>.properties à partir de la source anglaise.
  3. Relisez le fichier généré, corrigez à la main tout ce qui sonne mal, puis ouvrez une pull request.

Le script tools/i18n/translate-locales.js est incrémental : le relancer ne traduit que les clés qui n'existent pas encore dans le fichier cible, si bien que les corrections manuelles sont conservées à chaque mise à jour ultérieure du lanceur.
