JVM 预设

设置 → 高级中的 JVM 预设下拉菜单用于选择一组命名的参数， 启动器在启动 Minecraft 时会将这些参数传递给 JVM。这些参数用于调优垃圾回收器、 控制堆区域大小以及开关 GC 日志——它们不会改变游戏本身的 行为，只会改变承载游戏的 JVM 管理内存的方式。

对于大型整合包（200 个以上模组），选择合适的预设最为重要，因为在大量区块 加载和卸载之后，GC 需要进行大量清理。对于原版和小型整合包，任何预设都可以， 默认的“Performance”就很好用。

性能（Aikar 参数）

默认预设，推荐绝大多数用户使用。它使用 G1 垃圾回收器，并采用 Aikar（Paper Minecraft 服务器的作者）多年前发布、至今仍被许多教程引用的 参数调优。其设计目标是在高负载游戏时尽量减少 GC 停顿造成的卡顿。

适用于：分配了 6 GB 以上内存的整合包， 以及您发现在高负载下会周期性掉帧的 重度模组整合包。

低内存

精简的参数，适用于可用内存不多的系统。使用 G1，并采用 更短的停顿目标和更小的堆区域，以牺牲部分 吞吐量为代价，在内存紧张时获得更可预测的表现。

适用于：系统总内存 ≤ 8 GB 的电脑、 使用电池供电的笔记本电脑，或您希望在运行多个整合包的同时 运行其他应用的情况。不推荐用于大型整合包 （200 个以上模组），在相同的总内存分配下，Aikar's Flags 回收内存的效率 更高。

调试

在 Performance 参数的基础上，启用 GC 详细日志和 Java 断言。 会在整合包的安装文件夹中写入一个 {@code gc.log} 文件， 记录每次 GC 事件及其时间戳。主要适用于模组 开发者以及排查可复现的 OOM 崩溃的用户——它会带来 少量持续的性能开销，因此请不要在日常游戏中一直开启。

适用于：诊断 GC 停顿问题， 调查“每分钟都会无响应几秒钟”之类的 问题报告。

无

空参数列表——JVM 使用其自身的默认值。可用于 测试某个感知到的性能问题是否由预设参数本身引起 （这种情况少见，但当 JDK 版本比编写 Aikar's Flags 时 新得多时有可能发生）。

适用于：验证基准表现，即怀疑某个 预设与特定模组或 JDK 版本相互冲突时。

内存分配说明

预设在启动时调优 JVM，但 JVM 可以使用多少内存，由启动器在 设置 → 账户 / 游戏中的最小内存和最大内存滑块 决定。合适的内存大小取决于整合包：

  • 原版 Minecraft：2 GB 已足够。
  • 轻量整合包（≤ 50 个模组）：4 GB。
  • 中等整合包（50–150 个模组）：6 GB。
  • 重度整合包（150 个以上模组，含光影）：8–12 GB。
  • 超大型整合包（300 个以上模组，自定义世界生成）：12–16 GB。
警告

分配超出系统可用量的内存会导致 Minecraft 使用磁盘交换，从而让卡顿变得更严重，而不是更轻。 请将最大内存保持在系统总内存的一半或以下。 16 GB 的系统分配给 Minecraft 的内存不应超过 8 GB。

自定义参数

设置中预设下拉菜单下方的字段可以编辑——如果没有合适的预设， 您可以粘贴自己的参数字符串。 常见的追加参数：

  • -XX:+UseZGC — 切换到 Z 垃圾回收器 （低停顿，需要 JDK 15 或更高版本）。在 超大堆（32 GB 以上）上有时优于 G1，但在典型的 Minecraft 配置中 通常不值得从 G1 更换。
  • -Dfile.encoding=UTF-8 — 当模组在 Windows 上生成 含有非 ASCII 内容的配置文件、而 默认字符集可能为 Latin-1 时很有用。
  • -Xss2M — 将线程栈大小从 JVM 默认值调大；某些调用链很深的整合包（重度世界生成 模组、大型维度生成器）需要此参数。

自定义参数中的错误会表现为启动失败，并显示 “Error: Could not create the Java Virtual Machine”或 “Unrecognized VM option”之类的消息。如果看到这类消息，请先切换回 Performance 再试一次，而不是急于修改自定义字段。
